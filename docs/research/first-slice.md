# First control-plane slice: source and design evidence

Researched 2026-10-21. This is a new implementation. No inaccessible archive or source from another environment was read or imported. Product behavior is grounded in public AWS documentation; no Amazon proprietary implementation was consulted. Open-source infrastructure source was reviewed as noted below, so this is not a claim of formally isolated clean-room provenance for those infrastructure ideas.

## Scope and search

The initial slice needs Rust tenant/session identity, exact tool-request approval binding, terminal cancellation/revocation, and an explicit unknown-outcome state that cannot automatically retry an external write. AgentGateway is an external component, not a protocol to recreate. A small std-only state machine is sufficient for this slice; credentials, IdP validation, network dispatch, MicroVM workers, and BI are unavailable until implemented and independently tested.

Searches used the connected GitHub repository search for `agentgateway MCP proxy Rust`, `cedar policy authorization`, `rust journal durable append log` (zero results), and `sled embedded rust database`; public web searches covered official Quick/QuickSight behavior and delegated versus application identity. Repository search and actual file inspection are separate evidence; no upstream tests were executed.

## Actual source inspection

R1. AgentGateway [`crates/agentgateway/src/mcp/rbac.rs`](https://github.com/agentgateway/agentgateway/blob/f51a7fbca57dfe56bf639b8df21be49db76e9ebc/crates/agentgateway/src/mcp/rbac.rs): `McpAuthorizationSet::validate` constructs a CEL executor with tool/resource and method context; no rules returns true. Tests cover missing JWT claims denying a configured subject condition and merged deny policies surviving a higher-precedence allow. OpenQuick must require explicit deployed policy; simply putting a gateway in front is not evidence of approval enforcement.

R2. AgentGateway [`crates/agentgateway/src/mcp/session.rs`](https://github.com/agentgateway/agentgateway/blob/f51a7fbca57dfe56bf639b8df21be49db76e9ebc/crates/agentgateway/src/mcp/session.rs): `Session::send` takes request context and JSON-RPC messages and relays upstream; `stateless_send_and_initialize` handles protocol handshakes and upstream sessions. [`MCP README`](https://github.com/agentgateway/agentgateway/blob/f51a7fbca57dfe56bf639b8df21be49db76e9ebc/crates/agentgateway/src/mcp/README.md) distinguishes target-selection conditions from per-resource authorization and describes evolving version negotiation. This substantial protocol machinery stays upstream. OpenQuick session IDs are application control-plane identity, not assumed interchangeable with MCP session identifiers.

R3. AgentGateway [`crates/agentgateway/src/http/retry/mod.rs`](https://github.com/agentgateway/agentgateway/blob/f51a7fbca57dfe56bf639b8df21be49db76e9ebc/crates/agentgateway/src/http/retry/mod.rs): retry `Policy` has attempts, response codes, precondition and condition expressions. Configured response-code retries do not determine whether an external write happened. OpenQuick must record an execution intent before dispatch and hold uncertain writes for reconciliation; deployment must also disable proxy retries for writes. A core state machine alone cannot prove remote exactly-once execution.

R4. Cedar [`cedar-policy-core/src/authorizer.rs`](https://github.com/cedar-policy/cedar/blob/4d1ef853895d8a3fa8f3a6c9651b0eef21bf9edd/cedar-policy-core/src/authorizer.rs): `Authorizer::is_authorized_core_internal` separates permit/forbid/residual/error decisions; an empty policy set is denied in `authorizer_sanity_check_empty`. Erroring individual policies are skipped, so an error in a forbid policy is not a universal fail-closed guarantee. Do not claim a generic policy engine alone provides approval or credential isolation.

R5. sled [`src/flush_epoch.rs`](https://github.com/spacejam/sled/blob/e449d17111f4a097e1c66b6db241962ccb6a4136/src/flush_epoch.rs): `FlushEpochTracker::roll_epoch_forward` seals an epoch and returns completion notifications; `Completion::wait_for_complete` distinguishes completion from a mere mutation. [`tests/test_crash_recovery.rs`](https://github.com/spacejam/sled/blob/e449d17111f4a097e1c66b6db241962ccb6a4136/tests/test_crash_recovery.rs) spawns child processes with fault injection and repeatedly recovers. This is evidence of upstream test design, not tests run here. If a local journal is included, test restart and incomplete intents and explicitly limit filesystem/power-loss/concurrent-writer claims.

## Public product behavior and identity

- [Amazon Quick overview](https://docs.aws.amazon.com/quick/latest/userguide/what-is.html): public product scope includes connected research, automation and analytics; these are long-term comparison targets, not features implemented by this PR.
- [Quick Sight developer overview](https://docs.aws.amazon.com/quicksight/latest/developerguide/welcome.html): public BI and dashboard embedding behavior informs future requirements. No compatible API, renderer or data engine is implemented by this slice.
- [Quick approval review](https://docs.aws.amazon.com/quick/latest/userguide/approval-review.html): the documented approval cycle governs sharing flows, with submitted flows locked and changes requiring a new cycle. Per-tool execution approval binding in OpenQuick is this project's own security design; it must not be attributed as the AWS protocol or an equivalence claim.
- [Microsoft OBO](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-on-behalf-of-flow): delegated user identity/scopes travel through a middle tier; an app-only token is not an OBO user. [Client credentials](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-client-creds-grant-flow): application identity and application permissions support M2M independently of a user. These must remain distinct types and authorization paths. No token acquisition is implemented. Credentials must remain in trusted secret-handling components and must never enter model/worker context or serialized control-plane requests.

## Adopted boundary and verification

Use original std-only Rust types and state transitions for `crates/core`. Bind approval to the complete immutable request identity (tenant, session, request ID, tool, target, exact argument bytes, effect kind, principal/identity mode); require approval and terminal outcomes for both read and external-write requests, consume approval exactly once, reject cross-tenant/session substitutions, and deny cancelled/revoked or unknown-result dispatch. Keep `crates/gateway` as the integration boundary that explicitly rejects unavailable external dispatch, composed by `apps/openquick`. This is not a safe production gateway or a worker sandbox.

No upstream code was copied or rewritten. AgentGateway is reserved for future direct external use; Cedar and sled are reference-only comparisons. OpenQuick's project license is still undecided and must not be filled with a dependency's license. A std-only Cargo graph avoids third-party package selection for the first slice; future AgentGateway distribution still requires full transitive license and NOTICE review.

Verification: fmt, workspace tests, Clippy with warnings denied, locked build, CLI smoke, and a demonstrated red/green security regression. Require positive and negative approval cases, cross-boundary failures, cancellation/revocation, and unknown-result no-retry. Local recovery testing cannot establish hardware isolation, IdP correctness, remote-side retry behavior or power-loss durability.
